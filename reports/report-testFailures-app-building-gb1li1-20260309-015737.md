### Test Isolation Issues
Data-contamination (6) + strict-mode (1) = 7 failures (46.7%). While just under the 50% threshold, data contamination is clearly the dominant failure mode at 40% of all failures. The affected spec files and patterns:

- **Pricing Payment specs** (pricing-payment-deposit.spec.ts, pricing-payment-pricing.spec.ts): Tests sharing the same seed order (BK-003, BK-005) and mutating its values, causing downstream test assertions to see stale data.
- **Timeline spec** (timeline.spec.ts): 6 tests all sharing BK-001, with status transitions and timeline mutations contaminating subsequent tests.
- **Settings specs** (settings-form-save.spec.ts, sidebar-nav-display.spec.ts, settings-form-business-name.spec.ts): Tests modifying global settings (business name) that persist across tests within the same database branch.
- **JourneyQA** (worker 65): Destructive cleanup API call corrupting production data.

**Root cause:** All data contamination stems from tests sharing a single ephemeral Neon database branch within a spec file without resetting state between tests. The fix pattern is consistent: assign each mutating test its own dedicated seed data record, or add beforeEach hooks to reset state via API calls.

## 4. Recommendations

### `skills/debugging/*.md`
- **Add "wait-before-count" as a named pattern:** When tests count DOM elements (e.g., timeline entries, table rows), always wait for a specific element to be visible before counting. This pattern resolved 7 tests across 2 spec files.
- **Add "data-contamination diagnosis" shortcut:** When error output shows unexpected data values (wrong counts, wrong text), check if an earlier test in the same spec file mutates the same record. Page snapshots are often sufficient — skip Replay.
- **Add PlaywrightSteps→NetworkRequest as the default investigation sequence** for API-related failures. This two-step approach diagnosed 6 of 14 failures efficiently.

### `skills/tasks/build/testing.md`
- **Mandate dedicated seed data per mutating test:** Tests that modify database records (status changes, field updates, deletions) must use their own dedicated seed records, not shared ones. This would have prevented 6 of 15 failures (40%).
- **Add beforeEach state reset for settings tests:** Since settings are global (single row), any spec that tests settings modifications should reset settings to known defaults in a beforeEach hook.
- **Warn about onBlur vs onChange:** When testing form components that use onBlur for persistence, Playwright fill() alone won't trigger the save. Add `.blur()` after `.fill()` calls.
- **Warn about ESM __dirname:** If test helpers use `__dirname`, ensure ESM-compatible alternatives (`fileURLToPath(import.meta.url)`) are used.

### `skills/review/reportTestFailures.md`
- **Add REPLAY_NECESSARY as REQUIRED for all REPLAY_USED=yes entries:** One analysis file (bug-fix worker 2) omitted this field. Enforce that it's always present when Replay is used.
- **Add DIAGNOSED_FROM for Replay-used failures too:** Currently only required when REPLAY_USED=no, but capturing it for all failures would improve diagnostic source effectiveness analysis. Many Replay sessions confirm what error output already showed — DIAGNOSED_FROM would make this explicit.
- **Clarify infrastructure failure scope:** The current definition doesn't clearly cover recording upload failures that occur after tests pass. Worker 62 had a successful test but failed recording upload — it was correctly categorized as infrastructure but the distinction could be clearer.
